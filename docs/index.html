01

Tabs

Satu tab terlihat, sisanya tersimpan. Hanya tab aktif yang bisa dicapai dengan Tab; tab lain dicapai dengan panah, jadi pengguna keyboard tidak perlu melewati semuanya satu per satu.

Contoh
Ringkasan Pendapatan Arsip Ekspor

Rp 48,2 jt

Pendapatan bulan ini, naik 6% dari bulan lalu.

1.284

Transaksi tercatat sejak 1 Oktober.

Arsip sedang disiapkan.

Unduh laporan sebagai CSV atau PDF.

Keyboard

→ ←Pindah ke tab berikutnya atau sebelumnya, berputar di ujung. Tab nonaktif dilewati.
Home EndKe tab pertama atau terakhir.
Enter SpasiMemilih tab, bila activation="manual".
TabKeluar dari daftar tab, masuk ke panel yang aktif.
MarkupAtributMetode dan event 
<wc-tabs label="Laporan">
  <wc-tab>Ringkasan</wc-tab>
  <wc-tab>Pendapatan</wc-tab>
  <wc-tab disabled>Arsip</wc-tab>
  <wc-panel>...</wc-panel>
  <wc-panel>...</wc-panel>
  <wc-panel>...</wc-panel>
</wc-tabs>

02

Accordion

Dibangun di atas <details>, jadi isinya tetap bisa dibuka walau JavaScript gagal dimuat. Komponen menambahkan animasi tinggi, mode satu-terbuka, dan navigasi panah.

Contoh
Apakah perlu framework?

Tidak. Komponen ini adalah elemen kustom bawaan browser, jadi bisa dipakai di HTML biasa, PHP, WordPress, atau di dalam React dan Vue.

Bagaimana bila JavaScript mati?

Accordion tetap bekerja sebagai <details>. Semua panel tabs tampil berurutan. Dialog tidak tampil, karena memang butuh skrip untuk dibuka.

Bisakah tampilannya diubah?

Bisa. Semua warna, sudut, dan durasi diatur lewat variabel CSS. Coba bagian Tema di bawah.

Browser apa saja yang didukung?

Chrome, Edge, Firefox, dan Safari versi terbaru, termasuk Safari di iPhone. Tes otomatis berjalan di ketiga mesinnya.

Keyboard

Enter SpasiMembuka atau menutup bagian yang difokus.
↓ ↑Pindah ke judul berikutnya atau sebelumnya.
Home EndKe judul pertama atau terakhir.
MarkupAtribut, metode, event 
<wc-accordion single>
  <details open>
    <summary>Apakah perlu framework?</summary>
    <div>Tidak. ...</div>
  </details>
  <details>
    <summary>Bagaimana bila JavaScript mati?</summary>
    <div>...</div>
  </details>
</wc-accordion>
NamaJenisKeterangan
singleatributMembuka satu bagian menutup bagian lain.
toggle(i, paksa?)metodeBuka atau tutup bagian ke-i. Juga open(i) dan close(i).
wc-toggleeventdetail: { details, open, index }

03

Dialog

Memakai <dialog> bawaan untuk lapisan atas dan isi halaman yang tidak bisa disentuh, lalu menambahkan yang belum ada: fokus kembali ke tombol pembuka, klik latar untuk menutup, kunci scroll yang aman di iPhone, animasi keluar, dan event yang bisa dibatalkan. Di layar kecil, dialog muncul dari bawah.

Contoh

Event

  1. Buka salah satu dialog.

Keyboard

EscMenutup dialog, kecuali bila persistent.
TabBerputar di dalam dialog. Halaman di belakang tidak bisa difokus.
Saat ditutupFokus kembali ke tombol yang membukanya.
MarkupAtributMetode dan event 
<button data-wc-open="hapus">Hapus proyek</button>

<wc-dialog id="hapus">
  <h2>Hapus proyek ini?</h2>
  <p data-wc-desc>Semua berkas ikut terhapus.</p>
  <button data-wc-close="batal">Batal</button>
  <button data-wc-close="hapus">Hapus</button>
</wc-dialog>
AtributNilaiGunanya
openbooleanMembuka atau menutup dialog. Ikut berubah saat dialog dibuka pengguna.
labelteksNama dialog. Tanpa ini, judul pertama di dalamnya dipakai.
persistentbooleanEscape dan klik latar tidak menutup. Untuk langkah yang wajib diselesaikan.
centerbooleanTetap di tengah pada layar kecil, bukan lembar dari bawah.
data-wc-openid dialogPada tombol mana pun, untuk membuka dialog.
data-wc-closealasanPada tombol di dalam dialog, untuk menutup dengan alasan tersebut.
NamaJenisKeterangan
show() close(alasan) toggle()metodeclose mengembalikan false bila dibatalkan.
wc-openeventdetail: { opener }
wc-beforecloseeventBisa dibatalkan dengan preventDefault(), misalnya saat ada isian yang belum disimpan. detail: { reason }
wc-closeeventdetail: { reason }: escape, backdrop, button, nilai data-wc-close, atau api.
